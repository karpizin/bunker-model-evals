# Benchmark publication policy

This policy defines when a Bunker Model Evals result may be cited in product pages, presentations, articles, or comparisons.

## Result classes

Every published result must use one of these labels:

- **Reproduced** — generated by a committed runner and corpus, with complete configuration and retained aggregate evidence.
- **External** — copied from a named third-party publication or leaderboard and clearly attributed; it was not reproduced by this project.
- **Diagnostic** — a small sample, ablation, smoke test, or development run. It may guide engineering but must not be presented as a leaderboard result.

Mixing result classes in one table is allowed only when every row is labeled and the measurement differences are explained.

## Minimum reproducibility record

A reproduced result must identify:

1. repository commit and benchmark/scoring version;
2. corpus version and evaluated case count;
3. exact model repository, revision when available, file name, quantization, and checksum for local artifacts;
4. inference engine and version;
5. hardware, acceleration backend, context size, output limit, sampling, and timeout;
6. prompt or adapter mode and any retrieval budget;
7. number of requested, completed, failed, and excluded runs;
8. aggregation method and dispersion for repeated runs;
9. date of execution and known limitations.

Secrets, private hostnames, personal paths, and raw private inputs must be redacted without removing the parameters needed to reproduce the setup.

## Comparability

Rows in a ranking must use the same corpus, scorer, generation budget, failure policy, and aggregation method. If one dimension differs, split the table or mark the row non-comparable.

For LLM-judged metrics, record the judge model, prompt version, temperature, and retry policy. Keep deterministic checks separate from semantic-judge scores. A manual rescore must preserve the original raw answer and identify the reviewer or review rule.

## Integrity rules

- Never discard failed cases silently.
- Never replace a completed run because its score is inconvenient.
- Report benchmark-specific prompt tuning and validation-set iteration.
- Keep diagnostic subsets out of headline claims.
- Treat public benchmark answers as potentially contaminated training data.
- Preserve earlier reports when methodology changes; publish a new version instead of rewriting the old conclusion in place.

## Media and marketing use

Any external claim should link to the exact report, include the evaluation date, and state the measurement unit. “First place” or “best” requires a genuinely comparable table and must name the evaluated set; it must not imply a universal market ranking.

Before publication, run `make public-audit`, verify all links and cited numbers, and have a second reviewer check the claim against the retained artifact.
